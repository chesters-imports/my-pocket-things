# Features

Current features = what the shipping desk UI supports. The deepest idea is documented under {{link:crate.B160B0C0E0004B35|How it works}} and {{link:crate.B160B0C0E0004B36|Resort}}.

## Documents and vault

- Create / open `.sopr` documents in `safe_box`
- Vault manager: folders, rename, move, delete
- Empty state until a document is selected
- Document strip with path + open vault

## Compose

- Inline composer always at top of active section bucket
- Fragment types: text, image, table
- Stored frags stack below; stay on page
- No optional notes sidecar field
- Ctrl+Enter to store; Ctrl+L focuses composer
- New section: Ctrl+Shift+N

## Structure

- Sections rail + section order
- Stable `SPR-####` part codes
- Loose / unbinned intake bin
- Move parts between sections without renaming ids

## Views

- Document mode (Ctrl+1)
- Resort kanban (Ctrl+2)
- Print / reader with TOC (Ctrl+3; skips Loose)
- Keyboard shortcuts help dialog

## About this document

- Document menu → About this document…
- Meta + optional document-level `tps_chips` list
- Not printed into the reader body by default

## Storage and run

- Port **42950**
- Deck Host ROM `SPR-403` (`run-sopr.bat`, office profile)
- House format: `house: BIGBOX`, `product: sopr-documenter`

## Coming soon / ideas on the table

These are not live product promises on this desk:

- Full collaboration / CCC
- Per-fragment source-chip archaeology
- Treating chip lists as printed chrome
- BugBox (or "Bug Catcher") as a plugged-in bay — early idea only; not developed here
